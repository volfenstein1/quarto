1 Introduction

By now, there are many useful books, online guides, and videos for understanding the construction of Large Language Models from first principles (d2l?). What separates this project, is that this is designed as a mathematics first presentation of the architecture of GPT styled LLM. If you are a mathematician or are simply more comfortable with the language and structure of mathematical writing, this page will hopefully be an easy to digest presentation of the mathematical foundations of LLMs. You should be able to read and understand this material in an afternoon.

In addition to describing tokenizers, attention mechanisms, and transformer blocks in terms of mathematical formulas, I have included basic implementations of the constructions in PyTorch in order to also give a quick start for understanding the bridge between the abstract mathematical formulations and implementations in code. Because our focus is primarily on the mathematical constructions, we leave out some important elements of the computer engineering perspective which are important for implementation and optimization; namely, batching of data, differences between device architecture of CPU vs GPU, as well as parameter quantization.

This page was adapted from a project at Ruhr-Universität Bochum. Thanks go to the symplectic group at the Faculty of Mathematics!

1.1 Predicting the next token

We can superficially consider a (generative) \(\text{LLM}\) as a function which takes as input a fixed length sequence of text and outputs a probability distribution for the next text unit. By sampling from this distribution, and appending to the original text sequence, we can iteratively predict the subsequent text unit:

\[ \underline{\text{The Steenrod problem for}} \mapsto \begin{cases} \text{closed} & 29\% \\ \text{spaces} & 24\% \\ \text{modules} & 22\% \\ \text{spectra} & 19\% \end{cases} \]

\[ \implies \text{The }\underline{\text{Steenrod problem for } \fbox{closed}} \mapsto \begin{cases} \text{orientable} & 37\% \\ \text{smooth} & 23\% \\ \text{topological} & 19\% \\ \text{homology} & 9\% \end{cases} \]

\[ \implies \text{The Steenrod }\underline{\text{problem for closed } \fbox{orientable}} \mapsto \begin{cases} \text{manifolds} & 77\% \\ \text{orbifolds} & 14\% \\ \text{surfaces} & 4\% \\ \text{varieties} & <1\% \end{cases} \]

2.2 Tokens

A token is an arbitrarily defined unit of text.

Level Description Illustration
word Each word is a token. \(\fbox{The} \fbox{Steenrod} \fbox{problem} \fbox{for} \fbox{closed} \fbox{orbifolds}\)…
subword Each word is divided into a subword, e.g., BPE. \(\fbox{The}\fbox{ Ste}\fbox{en}\fbox{rod}\fbox{ problem}\fbox{ for}\fbox{ closed}\fbox{ orb}\fbox{if}\fbox{olds}\)…
character Each character is a token. \(\fbox{T}\fbox{h}\fbox{e}\fbox{ }\fbox{S}\fbox{t}\fbox{e}\fbox{e}\fbox{n}\fbox{r}\fbox{o}\fbox{d}\fbox{ }\fbox{p}\fbox{r}\fbox{o}\fbox{b}\fbox{l}\fbox{e}\fbox{m}\)…

A vocabulary \(V\) is a set of tokens. We often augment a vocabulary with additional special tokens, e.g.,

\([\text{BOS}]\) Marks the beginning of text.
\([\text{EOS}]\) Marks the end of text.
\([\text{PAD}]\) A padding token used to fill a sequence to the required context length.
\([\text{UNK}]\) Represents parts of the input text not present in the vocabulary.

2.3 Tokenizers

Let \(\text{TEXTS}\) be defined as the the set of finite texts and let \(\text{Seq}(V)\) be defined as the set of finite sequences \((t_1, t_2,...,t_N)\) where \(t_i \in V.\) A tokenizer \(T\) is a map

\[\begin{align} T: \text{TEXTS} &\to \text{Seq}(V), \\ \text{text} &\mapsto \text{tokenized text}. \end{align}\]

In other words, the tokenizer \(T\) encodes a text into a sequence of tokens. The (partial) inverse, \(T^{-1}\), decodes a sequence of tokens into a text. Note that the presence of characters or subwords not present in the vocabulary, as well as the possibility of special tokens, complicates the question of whether \(T\) is injective/bijective/neither as well as the definition of the (partial) inverse \(T^{-1}\).

For example, a word-level tokenizer can be viewed as follows:

\[ T(\text{The Steenrod problem...}) = (\fbox{The},\fbox{Steenrod},\fbox{problem}...) \]

2.4 Encoding

We next want to represent tokens numerically as vectors. The One Hot Encoding is a bijection between the tokens in a vocabulary \(V\) with the standard basis elements \(\{e_i\}\) in the space \(\mathbb{R}^{|V|}\), i.e.,

\[ \begin{align} \text{OHE}: V &\to \mathbb{R}^{|V|} \\ t_i &\mapsto e_i. \end{align} \]

This time, the inverse is unambiguously well-defined and is called a decoder.

By composing the tokenizer and the encoder, a finite text is represented as a sequence of indices representing the basis elements of \(\mathbb{R}^{|V|}\):

\[ \text{OHE}\circ T ( \text{The Steenrod problem...}) = (341, 12459, 948,...) \]

2.5 Subword tokenizer: byte-pair encoding

The byte-pair encoding is an algorithm which takes a source text and builds a vocabulary iteratively by combining the most common pairs of neighboring tokens (the modern version of the ‘byte-pair’). A text is correspondingly tokenized and encoded by this vocabulary by merging pairs of tokens iteratively.

Explicitly, the vocabulary is constructed via the following algorithm:

  • Initiate the vocabulary from the source text by taking the set of all characters appearing in the text; \[\text{vocabulary} := \{\text{character } | \text{ character} \in \text{TEXT}\}.\]
  • On each iteration, identify the most frequent pair of neighboring tokens. Add this pair as a new token in the vocabulary.
  • Repeat until the desired size of the vocabulary is reached.

A text is then tokenized and encoded via the following algorithm:

  • First, tokenize the text into a sequence of characters.
  • Iteratively, find the most frequent pair of adjacent tokens in the sequence that corresponds to a merged token in the learned vocabulary.
  • Replace this pair with the corresponding merged token.
  • Repeat until no more merges can be performed.

2.6 Tokenizers in python

Character

Character level tokenizer 
class CharacterTokenizer:
    def __init__(self):
        # Maps token_str to token_id (e.g., {"a": 19, "b": 23})
        self.vocab = {}
        # Maps token_id to token_str (e.g., {19: "a", 23: "b"})
        self.inverse_vocab = {}
        # Included special tokens
        self.specials = {"<|BOS|>", "<|EOS|>", "<|UNK|>", "<|PAD|>"}

    def initialize_vocab(self, source_text, allowed_specials=set()):
        """Initializes the vocabulary consisting of characters appearing in source_text."""
        characters = set(source_text)
        self.vocab = {char: idx for idx, char in enumerate(characters | self.specials)}
        self.inverse_vocab = {idx: char for char, idx in self.vocab.items()}

    def encode(self, text):
        processed = (
            ["<|BOS|>"]
            + [char if char in self.vocab else "<|UNK|>" for char in text]
            + ["<|EOS|>"]
        )
        ids = [self.vocab[token] for token in processed]
        return ids

    def decode(self, ids):
        return "".join(
            [
                self.inverse_vocab[id]
                for id in ids
                if self.inverse_vocab[id] not in self.specials
            ]
        )

BPE

Byte-pair encoding tokenizer 
class BPETokenizer:
    def __init__(self):
        # Maps token_str to token_id (e.g., {"symplectic": 11246})
        self.vocab = {}
        # Maps token_id to token_str (e.g., {11246: "symplectic"})
        self.inverse_vocab = {}
        # Included special tokens
        self.specials = {"<|BOS|>", "<|EOS|>", "<|UNK|>", "<|PAD|>"}
        # Dictionary of BPE merges: {(token_id1, token_id2): merged_token_id}
        self.bpe_merges = {}

    def initialize_vocab(self, source_text, vocab_size):
        """Initializes the vocabulary for BPE from source_text of size vocab_size."""
        from collections import Counter

        # Initialize vocab with unique characters appearing in the source_text

        # The first 256 ASCII characters
        initial_chars = {chr(i) for i in range(256)}
        # Additional characters appearing in the source_text
        source_chars = {char for char in set(source_text) if char not in initial_chars}

        self.vocab = {
            char: idx for idx, char in enumerate(initial_chars | source_chars)
        }

        # Add special tokens
        for special in self.specials:
            new_id = len(self.vocab)
            self.vocab[special] = new_id

        self.inverse_vocab = {idx: char for char, idx in self.vocab.items()}


        # Tokenize the source_text into token IDs
        token_ids = [self.vocab[char] for char in source_text]

        # Iteratively find and replace with a new_id the most frequent pairs of token ids appearing in token_ids.
        num_merges = vocab_size - len(self.vocab)
        for i in range(num_merges):
            # Identify the most frequent pair
            pairs = Counter(zip(token_ids, token_ids[1:]))
            if not pairs:
                break

            pair_ids = max(pairs, key=pairs.get)

            # Replace [pair_ids[0], pair_ids[1]] with new_id
            new_id = len(self.vocab)
            token_ids_merge = []
            j = 0
            while j < len(token_ids):
                if j < len(token_ids) - 1 and (token_ids[j], token_ids[j+1]) == pair_ids:
                    token_ids_merge.append(new_id)
                    j += 2
                else:
                    token_ids_merge.append(token_ids[j])
                    j += 1

            token_ids = token_ids_merge
            # Record the pair_ids and the new_id
            self.bpe_merges[pair_ids] = new_id
            # Add the merged pair to the vocab
            merged_token = (
                self.inverse_vocab[pair_ids[0]] + self.inverse_vocab[pair_ids[1]]
            )
            self.vocab[merged_token] = new_id
            self.inverse_vocab[new_id] = merged_token

    def encode(self, text):
        """Encode the input text into a list of token ids."""
        import re

        token_ids = []
        token_ids.append(self.vocab["<|BOS|>"])

        # Initial tokenization by character
        tokens = [self.vocab.get(char, self.vocab["<|UNK|>"]) for char in text]

        # Apply BPE merges
        while True:
            pairs = list(zip(tokens, tokens[1:]))
            # Find pairs that are in our merge list
            merge_candidates = {pair: self.bpe_merges[pair] for pair in pairs if pair in self.bpe_merges}

            if not merge_candidates:
                break # No more merges to apply

            # Find the merge with the lowest index (earliest learned)
            best_pair = min(merge_candidates, key=merge_candidates.get)
            new_id = self.bpe_merges[best_pair]

            # Apply the merge
            new_tokens = []
            i = 0
            while i < len(tokens):
                if i < len(tokens) - 1 and (tokens[i], tokens[i + 1]) == best_pair:
                    new_tokens.append(new_id)
                    i += 2
                else:
                    new_tokens.append(tokens[i])
                    i += 1
            tokens = new_tokens

        token_ids.extend(tokens)
        token_ids.append(self.vocab["<|EOS|>"])
        return token_ids

    def decode(self, ids):
        return "".join(
            [
                self.inverse_vocab[id]
                for id in ids
                if self.inverse_vocab[id] not in self.specials
            ]
        )

2.7 Token embeddings

We may compose this bijection with a map \(A :\mathbb{R}^{|V|} \to \mathbb{R}^{d_\text{model}}\) to obtain continuous vector representations of the tokens in the vocabulary:

\[ \text{Embedding} := A \circ \text{OHE}: V \to \mathbb{R}^{d_\text{model}}. \]

This composition is the basis of the Word2vec family of embeddings. The map \(A\) is often a linear map, or, if we wished, a neural network itself; in the process of training the GPT, we can adjust the weights to learn better token embeddings. In PyTorch, this is implemented as torch.nn.Embedding, which acts as a lookup table mapping token indices to dense vectors.

```{python}
#| code-summary: "Token embedding example"
tokenizer = BPETokenizer()
tokenizer.initialize_vocab(text, 300)
sentence = "A symplectic manifold"
encoded_sentence = tokenizer.encode(sentence)

X = torch.tensor(encoded_sentence)
# d_model = 5
emb_layer = torch.nn.Embedding(tokenizer.vocab.__len__(), 5)
print("Embedded sentence shape:", emb_layer(X).shape)
```

3 Attention

The goal of the attention mechanism is to produce a new representation for each token in a sequence that incorporates information from other tokens. For a given token, tokens that are more relevant should have a stronger influence on its new representation. We implement causally masked self-attention, which is the standard for decoder-only transformers like GPT.

Given an input sequence of tokens \((t_1,...,t_N)\), we associate to it a sequence of embedded \(d\)-dimensional vectors \((x_1,...,x_N)\), which we may consider as a matrix \(X \in \mathbb{R}^{N\times d}\).

The formula for scaled dot-product attention is:

\[ \text{attention}(Q,K,V) := \text{softmax} \left( \frac{QK^T}{\sqrt{d_k} } + M \right) V \]

where \(Q, K, V\) are the Query, Key, and Value matrices, \(d_k\) is the dimension of the key vectors, and \(M\) is a mask.

3.1 Positional encoding matrix

Since the attention mechanism itself does not have an intrinsic notion of sequence order, we must supply this information externally. This is achieved by adding a positional encoding matrix \(P \in \mathbb{R}^{N\times d}\) to the input embedding matrix. The entries \(p_{ij}\) are given by:

\[ p_{i,2j} := \sin \left( \frac{i}{10000^\tfrac{2j}{d}}\right), \qquad p_{i,2j + 1} := \cos \left( \frac{i}{10000^\tfrac{2j}{d}}\right). \]

where \(i\) is the position in the sequence and \(j\) is the dimension in the embedding.

Positional encoding 
class PositionalEncoding(nn.Module):
    def __init__(self, context_length, d_model):
        super().__init__()
        P = torch.zeros(context_length, d_model)
        position = torch.arange(0, context_length, dtype=torch.float).unsqueeze(1)
        div_term = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
        P[:, 0::2] = torch.sin(position * div_term)
        P[:, 1::2] = torch.cos(position * div_term)
        self.register_buffer('P', P)

    def forward(self, X):
        # X has shape (sequence_length, d_model)
        X = X + self.P[:X.size(0)]
        return X

3.2 Query, Key, and Value Matrices

The Query, Key, and Value matrices are obtained by applying linear transformations to the input matrix \(X\) (which includes positional encodings). Let \(W_Q, W_K, W_V \in \text{Mat}_{d \times d_k}(\mathbb{R})\) be learnable weight matrices. Then:

  • \(Q := X W_Q\) (Queries)
  • \(K := X W_K\) (Keys)
  • \(V := X W_V\) (Values)

Here, \(d_k\) is the dimension of the key/query vectors, typically set to \(d_k=d\).

3.3 Alignment Matrix

The matrix of attention scores, \(S = QK^T\), represents the alignment between tokens. The entry \(S_{ij}\) is the dot product of the query vector for token \(i\) and the key vector for token \(j\). A high value indicates strong alignment.

3.4 The Factor \(\sqrt{d_k}\)

The multiplicative factor \(\frac{1}{\sqrt{d_k}}\) is a scaling factor. If we assume the components of the vectors in \(Q\) and \(K\) are independent random variables with mean 0 and variance 1, then the dot product \(q_i \cdot k_j\) will have mean 0 and variance \(d_k\). Scaling by \(\frac{1}{\sqrt{d_k}}\) ensures the variance remains 1. This prevents the softmax function from saturating (i.e., producing gradients that are too small for effective learning).

3.5 Causal Mask

For a generative model, the prediction for token \(t_i\) should only depend on the preceding tokens \(t_1, ..., t_{i-1}\). The causal mask \(M\) enforces this. It is a matrix where \(M_{ij} = 0\) if \(j \leq i\) and \(M_{ij} = -\infty\) if \(j > i\). Adding this mask to the attention scores ensures that \(\text{softmax}(S+M)_{ij} = 0\) for all \(j>i\), effectively zeroing out the influence of future tokens.

3.6 Softmax

The softmax function is applied row-wise to the masked, scaled attention scores to produce the attention weights matrix, \(W_{attn} = \text{softmax}(\frac{QK^T}{\sqrt{d_k}} + M)\). Each row \(i\) of \(W_{attn}\) is a probability distribution representing the attention that token \(i\) pays to all other (preceding) tokens.

3.7 Context Vectors

Finally, the output of the attention mechanism is the matrix of context vectors, \(Z = W_{attn}V\). Each row \(z_i\) is a weighted sum of the value vectors, where the weights are given by the \(i\)-th row of the attention weights matrix. Thus, \(z_i\) is a new representation of token \(i\) that is enriched with contextual information from the sequence.

Causally masked attention 
class CausallyMaskedAttention(nn.Module):
    def __init__(self, d_in, d_out, context_length, qkv_bias=False):
        super().__init__()
        self.d_out = d_out
        self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
        # Register mask as a buffer to avoid it being considered a model parameter
        mask = torch.triu(torch.ones(context_length, context_length), diagonal=1)
        self.register_buffer('mask', mask.bool())

    def forward(self, x):
        # x has shape (batch_size, num_tokens, d_in)
        # for simplicity, we omit the batch dimension in this explanation
        num_tokens = x.shape[0]

        keys = self.W_key(x)      # (num_tokens, d_out)
        queries = self.W_query(x) # (num_tokens, d_out)
        values = self.W_value(x)  # (num_tokens, d_out)

        attn_scores = queries @ keys.T # (num_tokens, num_tokens)

        # Apply causal mask
        attn_scores.masked_fill_(self.mask[:num_tokens, :num_tokens], -torch.inf)

        # Scale and apply softmax
        attn_weights = torch.softmax(attn_scores / math.sqrt(self.d_out), dim=-1)

        context_vectors = attn_weights @ values # (num_tokens, d_out)
        return context_vectors

4.1 Layer normalization

Layer normalization is a technique to normalize the inputs across the features for each data sample. For a vector \(x \in \mathbb{R}^n\), it is defined as:

\[ \text{LayerNorm}(x)_i := \gamma_i \left( \frac{x_i - \mu}{\sigma}\right) + \beta_i \]

where \(\mu = \frac{1}{n}\sum x_i\) and \(\sigma^2 = \frac{1}{n}\sum (x_i - \mu)^2\). The parameters \(\gamma \in \mathbb{R}^n\) (scale) and \(\beta \in \mathbb{R}^n\) (shift) are learnable parameters, initialized to 1 and 0 respectively. This normalization is applied before the main sub-layers (attention and feed-forward) to stabilize training.

Layer normalization 
class LayerNorm(nn.Module):
    def __init__(self, emb_dim, eps=1e-5):
        super().__init__()
        self.eps = eps
        self.gamma = nn.Parameter(torch.ones(emb_dim))
        self.beta = nn.Parameter(torch.zeros(emb_dim))

    def forward(self, x):
        mean = x.mean(dim=-1, keepdim=True)
        var = x.var(dim=-1, keepdim=True, unbiased=False)
        norm_x = (x - mean) / torch.sqrt(var + self.eps)
        return self.gamma * norm_x + self.beta

4.2 Activation functions

An activation function introduces non-linearity into the model, allowing it to learn more complex patterns. A popular choice in transformers is the GELU (Gaussian Error Linear Unit) function:

\[ \text{GELU}(x) := x P(X\leq x), \qquad X \sim {\mathcal N}(0,1), \]

where \(P(X \leq x)\) is the cumulative distribution function of the standard normal distribution. It can be approximated by: \(\text{GELU}(x) \approx 0.5x( 1 + \text{tanh}[\sqrt{\tfrac{2}{\pi}}(x + 0.044715 x^3)] ).\)

GELU activation function 
class GELU(nn.Module):
    def __init__(self):
        super().__init__()

    def forward(self, x):
        return 0.5 * x * (1 + torch.tanh(
            math.sqrt(2.0 / math.pi) * (x + 0.044715 * torch.pow(x, 3))
        ))

4.3 Feed-forward layer

The feed-forward layer is a simple two-layer fully connected neural network applied independently to each position. It consists of a linear transformation to a higher-dimensional space (typically \(4d\)), an activation function, and a linear transformation back to the original dimension \(d\).

\[ \text{FFN}(x) = \text{GELU}(xW_1 + b_1)W_2 + b_2 \]

Feed-forward layer 
class FeedForward(nn.Module):
    def __init__(self, emb_dim):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Linear(emb_dim, 4 * emb_dim),
            GELU(),
            nn.Linear(4 * emb_dim, emb_dim),
        )

    def forward(self, x):
        return self.layers(x)

4.4 Transformer block

The full transformer block combines these components. The input x first passes through a layer normalization, then the causal attention mechanism. The output of the attention is added to the original input x (a residual connection). This sum is then passed through another layer normalization and the feed-forward network, followed by another residual connection.

Full Transformer Block 
class TransformerBlock(nn.Module):
    def __init__(self, d_model, context_length):
        super().__init__()
        self.att = CausallyMaskedAttention(d_model, d_model, context_length)
        self.ff = FeedForward(d_model)
        self.layer_norm1 = LayerNorm(d_model)
        self.layer_norm2 = LayerNorm(d_model)

    def forward(self, x):
        # Shortcut connection for attention block
        shortcut = x
        x = self.layer_norm1(x)
        x = self.att(x)
        x = x + shortcut  # Add the original input back

        # Shortcut connection for feed-forward block
        shortcut = x
        x = self.layer_norm2(x)
        x = self.ff(x)
        x = x + shortcut  # Add the original input back

        return x

4.5 Final Language Model

A full GPT-style model consists of:

  1. An embedding layer for input tokens.
  2. A positional encoding layer.
  3. A stack of several transformer blocks.
  4. A final layer normalization.
  5. A final linear layer (the “un-embedding” layer) that maps the output vectors to logits over the vocabulary.
Full Language Model 
class LanguageModel(nn.Module):
    def __init__(self, vocab_size, d_model, context_length, num_blocks):
        super().__init__()
        self.token_embedding = nn.Embedding(vocab_size, d_model)
        self.pos_encoding = PositionalEncoding(context_length, d_model)
        self.blocks = nn.Sequential(*[TransformerBlock(d_model, context_length) for _ in range(num_blocks)])
        self.final_norm = LayerNorm(d_model)
        self.output_head = nn.Linear(d_model, vocab_size, bias=False)

    def forward(self, idx):
        x = self.token_embedding(idx)
        x = self.pos_encoding(x)
        x = self.blocks(x)
        x = self.final_norm(x)
        logits = self.output_head(x)
        return logits

4.6 Inference

To generate text, we provide an initial sequence of tokens (the prompt), pass it through the model, and obtain logits for the next token. We can then sample from the probability distribution obtained by applying softmax to these logits (e.g., taking the argmax for greedy sampling) to select the next token. This new token is appended to the sequence, and the process repeats.

Text Generation 
def generate(model, ids, max_new_tokens, context_size):
    # ids is a tensor of shape (1, num_tokens)
    for _ in range(max_new_tokens):
        # Crop current context if it exceeds the supported context size
        ids_context = ids[:, -context_size:]

        # Get the predictions
        with torch.no_grad():
            logits = model(ids_context) # (1, num_tokens, vocab_size)

        # Focus only on the last time step
        logits = logits[:, -1, :] # (1, vocab_size)

        # Apply softmax to get probabilities
        probs = torch.softmax(logits, dim=-1)

        # Get the idx of the vocab entry with the highest probability
        id_next = torch.argmax(probs, dim=-1, keepdim=True)

        # Append sampled index to the running sequence
        ids = torch.cat((ids, id_next), dim=1)
    return ids

5 Training

5.1 Data loading

To train the model, we need to feed it chunks of the source text. We create a data loader that provides pairs of \((x, y)\), where \(x\) is a sequence of tokens (the context) and \(y\) is the next token in the sequence (the target).

Data Loader 
def create_dataloader(text, tokenizer, context_length, batch_size):
    token_ids = tokenizer.encode(text)
    X, Y = [], []
    for i in range(len(token_ids) - context_length):
        X.append(token_ids[i:i+context_length])
        Y.append(token_ids[i+context_length])

    X = torch.tensor(X)
    Y = torch.tensor(Y)

    dataset = torch.utils.data.TensorDataset(X, Y)
    dataloader = torch.utils.data.DataLoader(dataset, batch_size=batch_size, shuffle=True)
    return dataloader

5.2 Cross-entropy loss

The standard loss function for training a language model is the cross-entropy loss. Given the model’s output logits and the true next token, the loss measures how “surprised” the model was by the correct answer. For a single instance, if the model outputs a probability distribution \(p\) over the vocabulary and the true next token has index \(k\), the loss is:

\[ L = -\log(p_k) \]

This is equivalent to the cross-entropy \(H(q, p) = -\sum_i q_i \log(p_i)\), where \(q\) is the true distribution (a one-hot vector with a 1 at index \(k\)). Minimizing this loss encourages the model to assign a high probability to the correct next token.

5.3 Training Loop

The training process involves iterating through the data, calculating the loss, and updating the model’s parameters using an optimizer like Adam.

Training Loop 
# This is a conceptual example and is not meant to be run directly.
def train_model(model, dataloader, optimizer, num_epochs):
    loss_fn = nn.CrossEntropyLoss()
    for epoch in range(num_epochs):
        for inputs, targets in dataloader:
            # Forward pass
            logits = model(inputs) # (batch_size, context_length, vocab_size)

            # Reshape for loss function
            # We only care about predicting the next token for each context
            logits = logits.view(-1, logits.size(-1)) # (batch*context, vocab)
            targets = targets.view(-1) # (batch*context)

            # Calculate loss
            loss = loss_fn(logits, targets)

            # Backward pass and optimization
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
        print(f"Epoch {epoch+1}, Loss: {loss.item()}")

6 LoRA fine-tuning

Low-Rank Adaptation (LoRA) is a parameter-efficient fine-tuning (PEFT) technique. Full fine-tuning of a large pre-trained model is computationally expensive as it requires updating all of the model’s weights. LoRA proposes to freeze the pre-trained weights and instead inject smaller, trainable “rank decomposition” matrices into the layers of the model.

Mathematically, for a pre-trained weight matrix \(W_0 \in \mathbb{R}^{d \times k}\), the update during fine-tuning is constrained. Instead of learning a full-rank update \(\Delta W\), LoRA learns a low-rank representation of it. The modified forward pass becomes:

\[ h = W_0 x + \Delta W x = W_0 x + B A x \]

where \(W_0\) is frozen, \(B \in \mathbb{R}^{d \times r}\), \(A \in \mathbb{R}^{r \times k}\), and the rank \(r \ll \min(d, k)\). The only trainable parameters are \(A\) and \(B\). This significantly reduces the number of trainable parameters, making fine-tuning much more efficient.
